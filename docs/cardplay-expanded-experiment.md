# 扩大出牌训练与独立对战评估

实验日期：2026-10-25。本轮固定协议见 [protocol.json](../artifacts/cardplay-expanded-v1/protocol.json)，数据审计见 [data-audit.json](../artifacts/cardplay-expanded-v1/data-audit.json)。原始 pilot 记录保留在 [出牌验证](cardplay-validation.md)。

## 协议与隔离

| 项目 | 设置 |
|---|---|
| 数据目录 | `data/cardplay-expanded-v1/{train,valid,test}` |
| 训练 | 10,000 副，520,000 条出牌决策 |
| 验证 | 1,024 副，53,248 条决策；只用于选模 |
| 独立测试 | 1,024 副，53,248 条决策；全部候选冻结后评估 |
| 训练随机种子 | 42、43、44；均从同一个上一轮 SL best 初始化 |
| 每种子 SL | 1,000 步 × 64 条；每 100 步固定抽样 4,096 条验证，按 NLL 选 best |
| 每种子 PPO | 30 更新 × 32 副双室，2 epochs；每 5 更新在 128 副验证牌上对各自 SL 锚点评估并选 best |
| 总量 | 192,000 条 SL 抽样；2,880 副双室 PPO（5,760 室，149,760 条当前策略动作） |
| 主比较 | 各 PPO best 对各自 SL best，三种子的平均 IMP/副 |
| 次比较 | 各 SL/PPO best 对随机策略、上一轮 PPO pilot，共 15 组对战 |
| 最终对战 | 每组同一 1,024 副测试牌，双室实际打完，网络贪心，评估种子 20261025 |

完整发牌 ID 沿用对应叫牌监督集合，三个集合互不重叠，数据生成时逐局校验全部出牌及终局分数。扩大后的测试集合包含此前只做过正确性检查的 128 副，没有参与前轮选模或棋力评估。各模型仍使用北家发牌、无局、WBridge5 SAYC 来源的记录定约。

最终候选先写入不可覆盖的 `frozen-models.json`（模型 SHA256、选中步数、最终训练步数），再打开独立测试做对战。测试结果不反馈给本轮训练或选模；不从测试表现选出“最佳种子”。主结果对训练种子和相同牌局列分别重采样 5,000 次，报告区间；仅三个训练种子，种子不确定性的估计仍较粗糙。次比较作为探索结果，未做多重比较校正。

## 复现与恢复

```powershell
# 在本项目已有原始轨迹和叫牌监督集合的前提下准备独立目录。
.\.venv\Scripts\python.exe -m bridgemind.cardplay prepare --output data/cardplay-expanded-v1 --train-boards 10000 --valid-boards 1024 --test-boards 1024

# 固定协议分别执行；已存在的训练检查点会按原参数恢复。
.\.venv\Scripts\python.exe examples/cardplay_experiment.py --phase train
.\.venv\Scripts\python.exe examples/cardplay_experiment.py --phase evaluate
.\.venv\Scripts\python.exe examples/cardplay_experiment.py --phase report
```

`runs/cardplay-expanded-v1/{sl,ppo}-{42,43,44}/` 保存 best、last 和 PPO 历史池，均被 Git 忽略。`artifacts/cardplay-expanded-v1/` 保存固定协议、数据指纹、指标副本、冻结模型哈希、逐副对战和汇总。冻结后脚本拒绝继续训练本轮；评估中断可以重跑 `evaluate`，仅复用模型、数据、牌数及种子都匹配的结果。

## 数据加载改动

原先固定保留 4 个压缩分片，扩到 127 个训练分片后，均匀抽样会频繁解压。现改为每个 `PlayData` 实例按数组字节预算的 LRU，默认 1 GiB，约 624 MiB 可缓存本轮全部训练分片。超过预算时淘汰最久未用的分片；单个分片本身超过预算时仍保留该分片。预算不包含 Python 对象、调用方仍持有的数组视图或 GPU 内存，不是进程 RSS 的硬上限。

相同种子、相同批量的微基准见 [cache-benchmark.json](../artifacts/cardplay-expanded-v1/cache-benchmark.json)：20 MiB（约四分片）缓存预热后 10 个 64 条批次抽样约 3.60 秒；1 GiB 缓存约 0.0034 秒。仅比较抽样，不是端到端训练速度；回归测试核对缓存预算不会改变样本、编码和随机状态。

## 独立对战结果

三种子均完成全部训练目标，SL best 分别为第 1,000、1,000、900 步，PPO best 分别为第 20、5、10 次更新。训练阶段耗时约 481 秒，15 组独立对战约 380 秒（RTX 5070）。完整回归 82 项通过；原始测试记录见 [tests.json](../artifacts/cardplay-expanded-v1/tests.json)。

SL 在同一 4,096 条验证抽样上的初始 NLL 为 1.073765、准确率 51.44%；三个 best 的 NLL 分别为 1.035810、1.036976、1.037735，准确率为 56.01%、55.74%、54.91%。这些指标不与前轮不同验证抽样上的数值直接比较。

每个单元是同一 1,024 副独立测试牌上的平均 IMP/副，正数表示本轮模型获益：

| 训练种子 | SL 对随机 | PPO 对随机 | SL 对旧 PPO | PPO 对旧 PPO | PPO 对自身 SL |
|---:|---:|---:|---:|---:|---:|
| 42 | +0.474 | +0.752 | -0.650 | -0.441 | +0.104 |
| 43 | +0.639 | +0.572 | -0.495 | -0.344 | -0.013 |
| 44 | -0.032 | +0.173 | -0.569 | -0.219 | -0.115 |

将训练种子与公共牌局列同时纳入 bootstrap：

| 比较 | 三种子平均 IMP/副 | 95% 区间 | 属性 |
|---|---:|---|---|
| PPO 对自身 SL | **-0.008** | **[-0.232, +0.223]** | 预定主比较，没有证据支持 PPO 提升 |
| SL 对随机 | +0.360 | [-0.088, +0.774] | 探索比较，跨种子不稳定 |
| PPO 对随机 | +0.499 | [+0.105, +0.872] | 探索比较，对随机有优势的信号 |
| SL 对旧 PPO | -0.572 | [-0.871, -0.279] | 探索比较，三个种子点估计均落后 |
| PPO 对旧 PPO | -0.335 | [-0.645, -0.023] | 探索比较，三个种子点估计均落后 |

PPO 种子 44 在 128 副选模验证牌上的 best 为 +0.84375 IMP/副，而在独立测试上对自身 SL 为 -0.11523。这个对照说明小面板上的选模收益不能直接当作实战提升。次比较的区间未经多重比较校正，不能据此宣称普遍超过随机或评出最强模型；没有基于测试挑选某个种子。

本轮完成了扩大训练和独立评估，**没有验证出 PPO 改善，也没有得到超过旧 PPO 的新模型**。监督拟合改善与真实对战收益仍不一致，三个 SL 种子的随机对手成绩差异也较大。当前每个种子仅抽样 64,000 条 SL 决策，约为 520,000 条集合的 0.123 倍抽样量（有放回），不能视为充分训练或收敛。后续优先在验证集上扩大训练暴露量、扩大固定对手选模面板，并研究搜索蒸馏；任何新的效果结论需要新的独立留出牌。

最终结果由 [report.json](../artifacts/cardplay-expanded-v1/report.json) 保存。15 组对战共 15,360 个双室比较、30,720 室，共用同一 1,024 副不同发牌，不能当作 15,360 个独立牌局样本。对战只评估固定记录定约下的出牌能力，不包含叫牌改进、对人搭档体系适配、搜索增强或不同局况的泛化结论。

本轮测试牌现已用于报告，后续若依据这些结果修改训练或选模规则，再使用它只能作为已知基准，不能重新称为未触碰的独立测试。旧实验与本轮的交集复核见 [pilot-overlap-audit.json](../artifacts/cardplay-expanded-v1/pilot-overlap-audit.json)。
