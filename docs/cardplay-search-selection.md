# 搜索强度与时延的验证选择

日期：2026-10-25。本轮只做搜索配置比较和独立确认，不训练新网络，也不扩展 PPO。基线为长训三个种子中验证 NLL 最低的种子 42、第 50,000 步模型；它在本轮新测试上的结果不参与选模。

固定协议与模型哈希分别见 [protocol.json](../artifacts/cardplay-search-selection-v1/protocol.json)、[frozen-baseline.json](../artifacts/cardplay-search-selection-v1/frozen-baseline.json)。运行目录为 `runs/cardplay-search-selection-v1/`，实际进度以 `status.json` 为准，标准输出/异常在 `stdout.log`、`stderr.log`。

## 试验设计

1. 从既有 1,024 副验证牌中，以种子 20261030 固定选择 128 副；所有配置使用相同发牌、记录叫牌和局况。
2. 在该验证面板上评估纯网络，以及均匀约束采样、网络归属引导采样各 8、16、32 个样本，共 7 个配置。纯网络先作自对局对称性检查，其余 6 个配置的顺序固定随机化，减少顺序效应。
3. 只使用验证收益和时延，按下述预先固定的规则选择一个配置，并保存 `selected-configuration.json`，包括全部验证结果的哈希。
4. 冻结后仅将这个选定配置，在新的 1,024 副独立测试牌上与固定纯网络比较，评估种子为 20261031；不会根据测试分数改选其他配置。

所有对战交换双方阵营打两室，实际打完 52 张牌；纯网络贪心，搜索以采样世界的预期原始桥牌得分选牌，最终效果以实际 IMP 评估。PIMC 仍存在策略融合偏差，不能当作信息受限最优求解器。

## 预定选择规则

- 搜索配置需满足非强制动作平均时延不超过 **100 ms**，95 分位不超过 **250 ms**。
- 在合格配置中找到最高的验证平均 IMP；分数处于最高值 **0.25 IMP/副**以内的正收益配置视作工程取舍区间，选择平均非强制时延最低者。
- 若没有满足预算的正收益搜索配置，保留纯网络。完全同分时依次按样本数、配置 ID 确定，保证可复现。
- 这是验证集上的工程选型规则，不是显著性检验；验证区间作为探索结果展示，不能当作最终测试结论。

## 数据隔离

新集合位于 `data/cardplay-search-selection-v1/`，1,024 副、53,248 条重放决策。导入时校验出牌合法性和 OpenSpiel 终局计分。

排除所有旧训练/验证/测试数据、叫牌牌表库、历史对战报告中的发牌，以及此前已使用或预留的评估 ID 文件；只跳过用于提供候选 ID 的原始 `data/supervised/test/board-ids.npy`。剩余 4,848 个可用 ID 中按原始轨迹顺序导入 1,024 副，不与旧面板重复。

来源、文件哈希、交集与数据指纹见 [exclusion-audit.json](../artifacts/cardplay-search-selection-v1/exclusion-audit.json)、[data-audit.json](../artifacts/cardplay-search-selection-v1/data-audit.json)。新测试与排除集合、验证面板的交集均为 0。完整排除快照留在本机 `data/cardplay-search-selection-v1-excluded.npy`，不纳入 Git。

## 时延测量

- 本轮没有并行训练；每个试验开始前记录 GPU 状态，并拒绝与其他 Python CUDA 进程并行运行。
- 双方网络都按 batch=1 推理，当前策略按一次可见观察到合法动作返回计时，包含编码、推断、采样、DDS RPC 和 CPU 动作输出同步。
- 分别报告全部动作、非强制动作、强制动作的数量、平均值、50/95 分位及最大值。选型预算只使用非强制动作，避免强制牌比例混淆。
- 网络在验证面板外的一副验证牌上预热 3 次，不计时。每个搜索配置启用新的独立 DDS 服务，4 个工作线程，没有跨配置查询缓存/原生上下文复用；服务启动不计入单步时延，首个实际求解计入。
- GPU 网络与 CPU DDS 使用不同资源，报告反映本机该实现的端到端时延，不代表相同硬件成本下的算法复杂度比较。

已完成的纯网络自对局为零 IMP；该验证面板上非强制动作平均约 **3.31 ms**、95 分位约 **5.21 ms**。这与上轮两个训练任务并行时的约 17 ms 均值不同，说明上轮时延不能直接用于空闲设备的选型。

## 验证网格与已冻结的选择

7 个配置均完成相同 128 副验证牌的双室评估，全部搜索配置符合预定时延预算：

| 当前策略，对手均为固定 SL | 验证平均 IMP/副 | 非强制平均时延 | 非强制 95 分位 |
|---|---:|---:|---:|
| 纯网络自对局 | 0 | 3.31 ms | 5.21 ms |
| 均匀采样 8 | +7.3125 | 18.27 ms | 53.31 ms |
| 均匀采样 16 | +7.9609 | 28.52 ms | 84.94 ms |
| 均匀采样 32 | +7.3281 | 50.40 ms | 149.66 ms |
| 网络引导采样 8 | **+8.1094** | **21.41 ms** | **56.62 ms** |
| 网络引导采样 16 | +7.6641 | 32.18 ms | 90.47 ms |
| 网络引导采样 32 | +7.8203 | 53.98 ms | 153.21 ms |

按预定规则选择 **hybrid-8**。它既是本次最高验证均值，也是在取舍区间内较快的配置；均匀 8 样本虽然更快，但其点估计低于取舍区间。这里没有做“8 样本理论最优”或“所有网络引导采样都更强”的结论。

选型记录及所有验证结果的哈希已固定在 [selected-configuration.json](../artifacts/cardplay-search-selection-v1/selected-configuration.json)。验证中 hybrid-8 的非强制最大时延约 666 ms；95 分位预算不等于最大时延保证，原始报告保留最大值。

随后已启动 **hybrid-8 对纯网络**的新 1,024 副独立确认，模型和配置均不再改变。最终效果与测试时延以 `confirmation-hybrid-8.json`、`report.json` 为准；这两个文件完成前，不把上述 +8.1094 当作独立测试结论。当前状态看 `runs/cardplay-search-selection-v1/status.json`。

## 输出与恢复

```powershell
.\.venv\Scripts\python.exe examples/cardplay_search_benchmark.py --phase all
```

已有 worker 仍活着时拒绝重复启动。中断后，在模型、库实现、协议、数据和配置保持一致的前提下，可重新运行；已完成且校验一致的试验会复用，未完成试验从固定种子重做。不会在尚未确认状态的 DDS 服务中自动重提求解；每个服务都清理其实际进程。

可按 `prepare`、`tune`、`confirm`、`report` 单独恢复。每处理 8 副牌更新运行状态。验证网格输出 `validation-*.json`；选型后输出 `selected-configuration.json`；最终确认写入 `confirmation-*.json`，完成后生成 `report.json`。最终结论应以这两个完成产物为准，不把进行中的验证结果写成测试结论。

`cardplay/benchmark.py` 实现单步计时与选择规则，回归覆盖超预算过滤、取舍区间、回退、重复/非有限输入拒绝及非法或过期动作检查。最新完整测试为 **96 项通过**，在正式计时启动前执行，避免测试进程干扰 GPU 测量。
